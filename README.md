# Учебная виртуальная машина, вариант 23

Практическая работа № 3, ИКБО-12-25. Ассемблер и интерпретатор на
Python 3.11+. Используется стандартная библиотека, сборка и установка
дополнительных пакетов не требуются.

## Язык ассемблера

Одна команда на строку, в конце обязательна точка с запятой.
Комментарии начинаются с `#`. Регистр имён имеет значение.
Целые операнды задаются десятичными неотрицательными числами.

| Команда | Поля | Действие |
| --- | --- | --- |
| `ACC = 188;` | A=7, B=188 | Загрузить константу в аккумулятор. |
| `ACC = MEM[ACC];` | A=26 | Прочитать память по адресу из аккумулятора. |
| `MEM[771] = ACC;` | A=18, B=771 | Записать аккумулятор по адресу B. |
| `ACC = ACC + MEM[64];` | A=21, B=64 | Прибавить значение памяти к аккумулятору. |

B для константы занимает 23 бита (0–8388607), для адреса — 20 бит
(0–1048575). Программа проверяет диапазоны до формирования кода.
`src/assembler.py` разбирает текст, `src/instructions.py` задаёт
объекты промежуточного представления и проверяет поля.

## Ассемблер

```cmd
run.bat assemble src\examples\specification.asm -o output\spec.bin --test
set "PYTHONPATH=src"
py -3 -m unittest discover -s src\tests -v
```

Ассемблер записывает двоичный файл и сообщает количество команд.
`--test` выводит байты каждой команды в шестнадцатеричном формате.
В коммите первого этапа этот режим выводит поля A и B.
В Git Bash скрипт запускается как `bash run.sh`.

`src/codec.py` кодирует и декодирует команды в little-endian.
A занимает младшие 5 бит, B начинается с бита 5. LOAD занимает
4 байта, READ — 1, STORE и ADD — по 4. Неиспользуемые старшие
биты равны нулю. Декодер проверяет длину, код операции и резервные биты.
`src/output_file.py` заменяет выходной файл после полной записи.

Ассемблер принимает позиционный путь к исходнику, обязательный
`-o/--output` для бинарного файла и необязательный флаг `--test`.
Исходники читаются в UTF-8, также допускается BOM.

## Интерпретатор и память

```cmd
run.bat assemble src\examples\copy.asm -o output\copy.bin
run.bat run output\copy.bin -o output\copy.json --start 256 --end 279
```

`src/machine.py` реализует `VirtualMachine`. Команды загружаются с
адреса 0 в общий массив из 1048576 ячеек. Каждый байт команды
занимает одну ячейку, значение данных — одну целочисленную ячейку.
Программа читает и изменяет тот же массив. Поэтому запись в область
команд влияет на последующую выборку. Для команд требуются байтовые
значения ячеек, данные хранят целые числа Python без переполнения.
Ячейки вне загруженной программы изначально равны нулю.

`run` читает бинарный файл и сохраняет JSON-объект с адресами-ключами.
`--start` и `--end` задают включительный диапазон адресов.
Выполнение начинается с нулевого аккумулятора и завершается на исходном
конце программы. Отдельной команды остановки в спецификации нет.
Пример `copy.asm` сначала инициализирует массив по адресам 256–263,
затем копирует его в 272–279, используя косвенное чтение.

## Арифметика

```cmd
run.bat assemble src\examples\addition.asm -o output\addition.bin
run.bat run output\addition.bin -o output\addition.json --start 256 --end 258
```

Метод `add` прибавляет к аккумулятору значение ячейки по адресу B.
Пример `addition.asm` сохраняет оба операнда и результат в памяти.
Спецификация не задаёт ширину значения аккумулятора или переполнение
при сложении. Используются целые числа Python без усечения результата.

## Поэлементное сложение векторов длины 8

Программы в `src/examples/vectors` инициализируют X по адресам 256–263
и Y по адресам 272–279. Для каждого индекса вычисляется X[i] + Y[i],
результат сохраняется в новый вектор по адресам 288–295.
Команды для Windows cmd из корня проекта.

```cmd
run.bat assemble src\examples\vectors\ascending.asm -o output\ascending.bin
run.bat run output\ascending.bin -o output\ascending.json --start 288 --end 295
type output\ascending.json

run.bat assemble src\examples\vectors\sparse.asm -o output\sparse.bin
run.bat run output\sparse.bin -o output\sparse.json --start 288 --end 295

run.bat assemble src\examples\vectors\large.asm -o output\large.bin
run.bat run output\large.bin -o output\large.json --start 288 --end 295
```

`ascending.asm` использует встречные последовательности,
`sparse.asm` — данные с нулевыми элементами, `large.asm` — большие
числа, включая суммы за пределами 23-битного поля константы.
Исходные векторы сохраняются. Циклы отсутствуют в наборе команд УВМ,
поэтому восемь операций записаны последовательно.
Все три примера компилируются и исполняются тестами, которые проверяют
каждый элемент результирующего вектора и JSON-дампа.

## Модули и функции

| Модуль | Назначение |
| --- | --- |
| `instructions.py` | `Instruction.fields` возвращает A/B, `validate` проверяет поля по `SPECS`. |
| `assembler.py` | `parse_line` разбирает строку, `parse_program` собирает список команд. |
| `codec.py` | `encode`, `encode_program` формируют байты, `decode_at` разбирает одну команду. |
| `machine.py` | `VirtualMachine` хранит память, аккумулятор и счётчик команд. `check_address` проверяет адрес, `load/read/store/add` выполняют команды, `fetch` читает текущие байты, `run` исполняет программу, `dump` формирует диапазон памяти. |
| `output_file.py` | `write_file` записывает бинарный код и JSON через временный файл с заменой. |
| `main.py` | `main` обрабатывает CLI, `assemble` запускает ассемблер, `interpret` исполняет бинарный файл, `add_interpreter` задаёт параметры режима `run`. |

Ошибки исходника, файлов, кодов операций, длины команды, резервных
битов и адресов выводятся в stderr с кодом завершения 1.
Ошибки аргументов CLI возвращают код 2, успешная работа — 0.
Предыдущие выходные файлы сохраняются при ошибке трансляции или
исполнения. Создаются необходимые родительские папки выходного файла.

## Тесты

```cmd
set "PYTHONPATH=src"
py -3 -m unittest discover -s src\tests -v
```

В Git Bash или Linux.

```bash
PYTHONPATH=src python -m unittest discover -s src/tests -v
```

Проверяются промежуточные поля и байты всех четырёх тестов
спецификации, граничные значения, повреждённые бинарные программы,
копирование массива, сложение, общая память и три векторных примера.
Тесты CLI запускают приложение отдельными процессами и читают
созданные бинарные файлы и JSON.
Пять этапов разработки сохранены отдельными Conventional Commits.
